# نظام غيث للسيطرة اللوجستية — Ghaith Logistics Control System

نظام ويب عربي كامل (RTL) **للاستخدام الشخصي** — مركز قيادة لإدارة وتدقيق معاملات النقل الحكومي واللوجستيات النفطية: كتب تسهيل المهمة، إضافة السيارات، استمارات القطع، العقود وكتب الضريبة، سجل الاشتغال، جداول السائقين، المرفقات، وتوليد الكتب الرسمية Word وPDF.

النظام **ليس أرشيفاً فقط** — بل محرك ضبط جودة يمنع الخطأ قبل وصوله إلى الكتاب الرسمي.

> **الإصدار 1.1.0 — نمط الاستخدام الشخصي**: لا تسجيل دخول. التطبيق يفتح مباشرة على لوحة التحكم بهوية موحدة، مع بقاء سجل التدقيق الكامل والانضباط الداخلي. راجع `CHANGELOG.md`.

## التشغيل

```bash
cd logistics-system
npm install
npm run setup      # إنشاء قاعدة البيانات + زرع البيانات التجريبية
npm run dev        # التشغيل التطويري على http://localhost:3100
# أو للإنتاج:
npm run build && npm start
```

يفتح المتصفح على `http://localhost:3100` — **بلا تسجيل دخول** — مباشرة إلى لوحة التحكم.

على Windows: انقر نقراً مزدوجاً على `START-WINDOWS.bat`. على macOS/Linux: `./START-MAC-LINUX.sh`.

## الهوية والإعدادات

من شاشة **الإعدادات والصيانة**:
- اسم التطبيق (عربي/إنجليزي) واسم المالك — يظهران في الشريط الجانبي وسجل التدقيق والكتب.
- تذييل التقارير والمستندات المولدة (قابل للتحرير).
- المنتج الافتراضي.

كل الحركات تسجل بهوية المالك الموحدة: أعدّه / دققه / أصدره، مع الطوابع الزمنية.

## النسخ الاحتياطي وإعادة التعيين

من شاشة **الإعدادات والصيانة**:

- **نسخة احتياطية كاملة** — ملف `logistics-backup-YYYY-MM-DD-HH-mm.zip` يشمل قاعدة البيانات وكل المرفقات والكتب المولدة والقوالب وملف `backup-info.json`.
  - **الاستعادة**: أوقف التطبيق، انسخ `database/dev.db` من النسخة إلى `prisma/dev.db` ومجلد `storage` فوق الحالي، ثم أعد التشغيل.
- **مسح البيانات التشغيلية** — يحذف المعاملات والسائقين والاستمارات والمرفقات والكتب المولدة، ويبقي الأدلة (جهات/شركات/عقود/ضريبة/مسارات/مصادر) والقوالب والإعدادات وسجل التدقيق.
- **تصفير كامل** — يحذف كل البيانات التشغيلية والأدلة وسجل التدقيق، ويبقي بنية قاعدة البيانات وأنواع المعاملات والقوالب والإعدادات وهوية المالك.

كل إعادة تعيين تتطلب كتابة عبارة تأكيد **حرفية**، وتنفذ داخل معاملة قاعدة بيانات واحدة (لا حالة وسطى فاسدة)، وتسجل في سجل التدقيق.

## سير معاملة تسهيل مهمة

1. **إنشاء معاملة** — اختيار النوع يعرض المتطلبات وينشئ قائمة مهام ذكية (بنودها الشرطية ديناميكية).
2. **إدخال البيانات**: الجهة (من الدليل حصراً)، الشركة، العقد، الضريبة، المسار (من الدليل حصراً)، استمارات القطع، جدول السائقين (يدوياً أو استيراد Excel بمعاينة).
3. **فحص المعاملة** — محرك التدقيق يعرض الأخطاء الحرجة والتحذيرات مع مرجع كل كيان.
4. **توليد Word** — يظهر فقط بعد صفر أخطاء حرجة. كل نسخة تحفظ برقم (مسودة 1، 2…) ولا تستبدل القديمة.
5. **الاعتماد ثم إصدار PDF نهائي** — بعد صفر أخطاء + صفر تحذيرات (أو تجاوزها بسبب مسجل ببصمة دقيقة) + اكتمال القائمة.
6. المعاملة النهائية **تقفل** — التعديل يتطلب نسخة تصحيحية مرتبطة بالأصل.

## محرك التدقيق — أمثلة القواعد

- **السيارات**: العدد يحسب من الجدول ولا يكتب يدوياً؛ كشف تكرار الأرقام والتسلسل الناقص وعدم تطابق العدد المذكور.
- **استمارات القطع**: `المتبقية = المقطوعة − المجهزة` دائماً؛ رفض مجهزة > مقطوعة؛ تحذير عند إعادة استخدام استمارة من معاملة أخرى أو استمارة مغلقة؛ منع استمارة مذكورة غير مرفقة.
- **المسارات**: من الدليل حصراً؛ مطابقة مصدر التجهيز والمنتج.
- **العقود والضريبة**: منع الإصدار بلا ربط؛ كشف ضريبة لا تطابق العقد؛ منع كمية > المسموح.
- **المرفقات**: الإلزامية حسب النوع تمنع الإصدار؛ مرفق بلا ملف؛ مرفق غير مدقق.
- **التجاوز**: التحذيرات فقط قابلة للتجاوز، بسبب إلزامي، وببصمة دقيقة (نوع الخطأ + الحقل + مرجع الكيان) فلا يخفي تجاوزٌ أخطاءً أخرى.

## استيراد Excel

اختيار الملف يعرض **معاينة قبل الحفظ**: إجمالي الصفوف، الصالحة، المرفوضة، المكررة داخل الملف، المكررة مع الجدول الحالي، مع تنزيل الصفوف المرفوضة CSV. الحفظ ذري — فشل جزئي لا يترك بيانات فاسدة. يدعم رؤوس عربية/إنجليزية وCSV المصدر من Access.

## قوالب Word

ترفع من شاشة «قوالب Word» (DOCX يحتوي placeholders):

`{{BookNumber}} {{BookDate}} {{TargetDepartment}} {{BookSubject}} {{CompanyName}} {{Product}} {{PreviousBookNumber}} {{PreviousBookDate}} {{ContractNumber}} {{ContractDate}} {{TaxLetterNumber}} {{TaxLetterDate}} {{RouteName}} {{RoutesList}} {{CutFormsList}} {{DriversStartSeq}} {{DriversEndSeq}} {{DriversCount}} {{AttachmentsList}} {{FinalRequest}} {{PreparedBy}} {{FooterText}}`

وللجداول المتكررة (حلقات داخل صف الجدول):
`{{#Drivers}} {{seq}} {{name}} {{vehicle}} {{governorate}} {{vtype}} {{notes}} {{/Drivers}}` —
`{{#CutForms}} {{number}} {{date}} {{source}} {{cut}} {{loaded}} {{remaining}} {{/CutForms}}` —
`{{#Attachments}} {{idx}} {{title}} {{number}} {{/Attachments}}`

## التحويل إلى PostgreSQL

1. في `prisma/schema.prisma` غيّر `provider = "sqlite"` إلى `"postgresql"`.
2. في `.env` ضع `DATABASE_URL="postgresql://user:pass@host:5432/logistics"`.
3. `npm run setup`.

## توليد PDF

يتطلب Chromium/Chrome. يبحث النظام تلقائياً، أو حدد المسار في `.env`:
`CHROMIUM_PATH="/usr/bin/chromium"` — توليد Word لا يحتاج ذلك.

## استكشاف الأخطاء

| العرض | السبب والحل |
|---|---|
| «قاعدة البيانات غير مهيأة بعد» | نفّذ `npm run setup` ثم أعد التشغيل |
| فشل توليد PDF | ثبّت Chromium وحدد `CHROMIUM_PATH` |
| فشل `npm run setup` أول مرة | يحتاج إنترنت لتنزيل محرك Prisma — أعد المحاولة |

## قيود معروفة والمرحلة القادمة

- المخطط يدار بـ `prisma db push` (مناسب لـ SQLite شخصي) — عند الانتقال لـ PostgreSQL يستحسن التحول إلى `prisma migrate`.
- السائقون مرتبطون بالمعاملة (لا سجل مركزي دائم للمركبات بعد) — تقرير «السيارات والسائقون» يكشف التكرار عبر المعاملات.
- مقترح المرحلة القادمة: سجل مركبات مركزي مع تاريخ نشاط، احتساب المستهلك/المتبقي تلقائياً على مستوى العقد وكتاب الضريبة من مجموع الاستمارات، واستعادة النسخة الاحتياطية من داخل الواجهة.
