# نظام تدقيق وإدارة معاملات النقل اللوجستي

نظام ويب عربي كامل (RTL) لإدارة وتدقيق معاملات النقل الحكومي واللوجستيات النفطية: كتب تسهيل المهمة، إضافة السيارات، محاور التحميل، استمارات القطع، العقود وكتب الضريبة، سجل الاشتغال، جداول السائقين، المرفقات، وتوليد الكتب الرسمية بصيغة Word وPDF.

النظام **ليس أرشيفاً فقط** — بل محرك ضبط جودة يمنع الخطأ قبل وصوله إلى الكتاب الرسمي.

---

## التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS v4 |
| الخادم | Next.js API Routes |
| قاعدة البيانات | Prisma ORM — SQLite افتراضياً، قابلة للتحويل إلى PostgreSQL بسطر واحد |
| توليد Word | docxtemplater + قوالب DOCX بحقول `{{Field}}` |
| توليد PDF | Chromium بلا واجهة (playwright-core) بخط نسخ عربي مدمج |
| Excel | استيراد جداول السائقين (XLSX/CSV بما فيها المصدّر من Access) وتصدير التقارير |
| المصادقة | جلسات JWT موقعة (jose) + bcrypt |

## التشغيل

```bash
cd logistics-system
npm install
npm run setup      # إنشاء قاعدة البيانات + زرع البيانات التجريبية
npm run dev        # التشغيل التطويري على http://localhost:3100
# أو للإنتاج:
npm run build && npm start
```

### حسابات تجريبية (كلمة المرور للجميع `123456`)

| البريد | الدور | الصلاحيات |
|---|---|---|
| admin@example.com | مدير النظام | كل شيء + تجاوز التحذيرات + الحذف |
| entry@example.com | مدخل بيانات | إنشاء وتعديل المعاملات |
| reviewer@example.com | مدقق | الاعتماد والإعادة للتصحيح وإصدار PDF |
| viewer@example.com | مطالع | قراءة فقط |

### التحويل إلى PostgreSQL

1. في `prisma/schema.prisma` غيّر `provider = "sqlite"` إلى `"postgresql"`.
2. في `.env` ضع `DATABASE_URL="postgresql://user:pass@host:5432/logistics"`.
3. `npm run setup`.

### توليد PDF

يتطلب متصفح Chromium. يبحث النظام تلقائياً في المسارات الشائعة، أو حدده يدوياً:
```
CHROMIUM_PATH="/usr/bin/chromium"
```

## فكرة العمل (سير معاملة تسهيل مهمة)

1. **إنشاء معاملة** — اختيار النوع يعرض المتطلبات فوراً وينشئ **قائمة مهام ذكية** تلقائياً (بنودها الشرطية تظهر وتختفي حسب البيانات).
2. **إدخال البيانات** من التبويبات: الجهة (من الدليل حصراً)، الشركة، العقد، كتاب الضريبة، المسار (من الدليل حصراً)، استمارات القطع، جدول السائقين (يدوياً أو استيراد Excel).
3. **فحص المعاملة** — يشغّل محرك التدقيق الذكي ويعرض كل الأخطاء الحرجة والتحذيرات.
4. **توليد كتاب Word** — يظهر فقط بعد صفر أخطاء حرجة. كل نسخة تحفظ برقم (مسودة 1، مسودة 2…) ولا تستبدل القديمة.
5. **اعتماد المدقق** ثم **إصدار PDF نهائي** — يظهر فقط بعد: صفر أخطاء + صفر تحذيرات (أو تجاوزها بصلاحية مدير مع تسجيل السبب) + اكتمال قائمة التدقيق.
6. بعد الإصدار تصبح المعاملة **نهائية مقفلة** — أي تعديل يتطلب **نسخة تصحيحية** مرتبطة بالأصل.

## محرك التدقيق الذكي — أمثلة القواعد

- **السيارات**: العدد لا يُكتب يدوياً بل يحسب من الجدول؛ كشف تكرار أرقام السيارات، التسلسل الناقص، وعدم تطابق العدد المذكور مع الجدول (يمنع الإصدار).
- **استمارات القطع**: `المتبقية = المقطوعة − المجهزة` دائماً؛ يرفض مجهزة > مقطوعة أو متبقية سالبة؛ تحذير عند إعادة استخدام استمارة من معاملة سابقة أو استمارة مغلقة؛ منع استمارة مذكورة غير مرفقة.
- **المسارات**: تُختار من الدليل حصراً؛ مطابقة مصدر التجهيز مع بداية المسار ومع منتج المعاملة.
- **العقود والضريبة**: منع معاملة تحتاج عقداً/ضريبة بدون ربط؛ كشف كتاب ضريبة لا يطابق العقد؛ منع كمية مطلوبة > المسموح بها.
- **المرفقات**: المرفقات الإلزامية حسب نوع المعاملة تمنع الإصدار إن نقصت؛ مرفق مذكور بلا ملف؛ مرفق إلزامي غير مدقق.
- **العنوان والجهة**: عنوان مخصص يتطلب تأكيداً؛ الجهة من الدليل حصراً مع كشف الجهات غير الفعالة.

## قوالب Word

ترفع القوالب من شاشة «قوالب Word» (DOCX يحتوي placeholders):

`{{BookNumber}} {{BookDate}} {{TargetDepartment}} {{BookSubject}} {{CompanyName}} {{Product}} {{PreviousBookNumber}} {{PreviousBookDate}} {{ContractNumber}} {{ContractDate}} {{TaxLetterNumber}} {{TaxLetterDate}} {{RouteName}} {{RoutesList}} {{CutFormsList}} {{DriversStartSeq}} {{DriversEndSeq}} {{DriversCount}} {{AttachmentsList}} {{FinalRequest}}`

وللجداول المتكررة (حلقات داخل صف الجدول):
`{{#Drivers}} {{seq}} {{name}} {{vehicle}} {{governorate}} {{vtype}} {{notes}} {{/Drivers}}`
`{{#CutForms}} {{number}} {{date}} {{source}} {{cut}} {{loaded}} {{remaining}} {{/CutForms}}`
`{{#Attachments}} {{idx}} {{title}} {{number}} {{/Attachments}}`

يزرع النظام 4 قوالب افتراضية جاهزة (تسهيل مهمة، تأييد عدم تجهيز، إضافة سيارات، كتاب عام).

## البيانات التجريبية المزروعة

- 4 مستخدمين بالأدوار الأربعة
- 6 جهات رسمية، شركتان، 4 مصادر تجهيز، 3 مسارات
- عقد + كتاب ضريبة مرتبط به
- 10 أنواع معاملات بقوائم تدقيقها وقواعدها ومرفقاتها الإلزامية
- 4 قوالب Word
- معاملة تسهيل مهمة نموذجية كاملة: 12 سائقاً، استمارتا قطع، سجل اشتغال، 6 مرفقات (أحدها ناقص عمداً لعرض عمل محرك التدقيق)
- نموذج في سجل الأخطاء

## ملاحظات تشغيلية

- الملفات (مرفقات، كتب مولدة، قوالب) تحفظ في `storage/` — احرص على نسخها الاحتياطي مع ملف `prisma/dev.db`.
- تصدير أرشيف أي معاملة ZIP كاملاً من زر «أرشيف ZIP» داخل ملف المعاملة.
- كل حركة (إنشاء، تعديل، تجاوز تحذير، توليد، إصدار) تسجل في **سجل التعديلات** باسم المستخدم والوقت.
